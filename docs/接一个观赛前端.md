# 接一个观赛前端

## 这个仓为什么没有前端

引擎侧是全的：开赛、赛程、投票、榜、赛录导出都有 HTTP 端点。**界面故意没有放进来。**

不是没做——是它做在了主项目里，跟那边的路由、抽屉、样式绑在一起，
拷过来你也跑不起来，反而会变成一层要维护的壳。这个仓只负责赛制本身：
抽签、轮次、时限、盲审、票、赛录。**比赛长什么样，是接的人自己的事。**

推流也是同一个态度：`arena/emitter.py` 是可插拔出口，
实现一个 `emit()` 就能把发言播进聊天室、WebSocket、Discord 或任何地方，引擎一行不用改。

下面是做界面真正需要的东西。

## 你需要的端点

挂上两个 router 就全有了：

```python
from fastapi import FastAPI
from arena import room, audience

app = FastAPI()
app.include_router(room.router)
app.include_router(audience.router)
# 队列要活过重启：在 lifespan 里 await room.debate_queue_startup()
```

| 端点 | 方法 | 干什么 | 返回里要看的 |
|---|---|---|---|
| `/api/debate/status` | GET | 现在在不在打 | `running`、`run_id`、`runs[]`（多场并行时全在这）、`max_concurrent` |
| `/api/debate/board` | GET | 选手榜 | `table[]`（`key/played/won/win_rate/mvp/audience_favorite`）、`matches`、`decided`、`skipped_unplayed`；`?by=name` 按席位、`?by=audience` 是观众榜 |
| `/api/debate/{run_id}/votes` | GET | 看票 | 见下 |
| `/api/debate/{run_id}/vote` | POST | 投票 | 见下 |
| `/api/debate/start` | POST | 开一场 | |
| `/api/debate/queue` | GET/POST/DELETE | 排队 | |
| `/api/debate/topics` | GET | 题库 | |

## 观众票

投票：

```jsonc
POST /api/debate/{run_id}/vote
{
  "voter_id": "浏览器里稳定存着的 id",   // 一人一票按它去重，刷新后必须还是同一个
  "voter_kind": "human",                // human | ai
  "side": "pro",                        // pro | con
  "favorite": "正方一辩",                // 可选，必须是这场的席位名
  "reason": "为什么（可选，≤100 字）"      // 可选就是真可选：不写不影响任何事
}
```

**理由不要做成必填。** 后端只校长度、不校有无；界面上也别把它摆在必经之路上——
真人观众多数是看完直接点一边就走的，逼他写一句话只会让他不投。

看票 `GET /api/debate/{run_id}/votes?voter_id=…`，两种形态，靠 `open` 分：

```jsonc
// 投票期
{"run_id": "...", "open": true, "total_voters": 12,
 "mine": {"side": "pro", "favorite": null, "conflict": false},   // 没投过就是 null
 "note": "盲投中：评委公示前看不到分布。"}

// 公示后
{"run_id": "...", "open": false, "voters": 12, "all": {"pro": 7, "con": 5},
 "unaffiliated": {"pro": 5, "con": 5},      // 剔掉利益相关者之后的票
 "audience_pick": "pro", "audience_favorite": ["正方一辩"], "ballots": [...]}
```

四条规矩，做界面时别绕开：

- **投票期不给任何分布**，连总票数的正反拆分都不给。评委没公示之前放出风向，
  投票就变成跟风。
- **自己那票的字段叫 `mine`**，不是 `my_vote`。写错的话投过票也不回显，
  按钮会永远停在「投这边」——JS 里 `undefined` 是合法值，类型检查拦不住这种错。
- **可以改票**，最后一次算数，`revisions` 会记改了几次。
- **利益回避是自动的**：投票人 id 撞上这场的席位名，票照收但标 `conflict`，
  汇总里 `unaffiliated` 是剔掉这些之后的干净票。

## 发言怎么进你的界面

不要轮询赛录文件。实现 `Emitter`：

```python
from arena import emitter

class MyRoom(emitter.Emitter):
    async def emit(self, body, *, title, kind, notify, run_id, meta):
        await my_chat.post(f"{title}\n{body}")
        return "msg-id"        # 返回宿主侧消息 id；辩手用它做 [[quote:#尾6位]] 精确引用

emitter.set_emitter(MyRoom())
```

不关心引用功能就返回空串，引擎会退回自增序号。

## 落盘的东西

- 赛录：`$DEBATE_DATA_DIR/<run_id>.json`（默认 `data/debates/`），
  含 `transcript`、`crossfire_log`、`ballots`、`audience`、`roster`
- 票箱：`$DEBATE_DATA_DIR/votes/<run_id>.json`
- 导出 md / PDF：`tools/export.py`

## 两句话的设计口径

**默认是裸场。** 席位拿到的 system prompt 只有辩题、立场、职能、字数、轮次、语言底线——
不教它怎么论证。实测过：把论证方法论注进 prompt，辩手会把方法里的选项原样搬成
发言小标题，读起来像做题；同题同模型的裸场组反而打出了真交锋。
**给方法就是给模板**，模型不会把方法内化成内功，它会把列表当填空题。
想做对照实验，`_run_match(coached=True)`。

**资料是递过去的，不是要求的。** 放进 `DEBATE_REFERENCE_DIR` 的 md 会随每席第一次出题
递给外部 Agent（它在自己家跑，读不到赛场的文件系统），资料包里写死一句
「看不看由你决定，不看不扣分」。这句不是客套——评委只看场上说了什么。
细节见 `external-agent-protocol-v2.md` 的 `references` 一节。
